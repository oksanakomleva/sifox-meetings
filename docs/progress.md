# Прогресс

_Обновлено: 2026-06-16._

## Сделано и в проде

### Запись встреч (ядро)
- Дедупликация встреч по `google_event_id` (раньше по `meeting_url`) — каждое occurrence = своя строка.
- Guard «один протоколлер на комнату» (дубли помечаются `error`).
- Фикс зависающего ffmpeg; конвертация WAV→MP3 (хранится только MP3); админ-страница «Хранилище».
- **Перенесённые встречи**: если бота уже водили на старое время (`done`/`error`), а событие перенесли — создаётся новая `pending`-встреча, старая архивируется (`google_event_id=NULL`), ссылка календаря перепривязывается. (`upsert_meeting`, commit `e562258`.)
- Разметка спикеров в транскрипте — по **большинству перекрытия** сегмента с таймлайном (устойчиво к лагу опроса и сегментам через смену спикера).

### AI
- **Чат** (по встрече и общий): в контекст идут **полные транскрипты** (с разбивкой по участникам), не протоколы; общий чат — за 90 дней, упаковка под бюджет символов.
- **Итоги недели**: кэш в `week_summaries` (инвалидируется по набору встреч + хэшу промпта), компактный «скиммабельный» формат, контекст — полные транскрипты.
- **Протокол**: строится по полному транскрипту (а не первым 8000 символов), на `CHAT_MODEL`.
- **Теги**: промпт ставит теги по заказчику/проекту/продукту (без мелочей), учитывает название встречи и переиспользует уже использованные теги. Ручное редактирование тегов в вебе + фильтр/поиск по тегам. Был разовый пакетный reanalyze существующих встреч.

### UI / админка
- Фавиконка: адаптивная под тёмную/светлую тему, затем квадратный знак «S».
- «Режим пользователя» (preview): только **свой** аккаунт, отдельная кука `preview` (админская сессия не теряется), баннер выхода; превью-сессия всегда не-админская.
- **Демо-режим** (тумблер поверх preview): реальные встречи с тегом `демо` (сам тег скрыт), фейковый раздел «Звонки» (лента → детали → AI-анализ), итоги недели по `демо`-встречам + фейковым звонкам, скрыт раздел «Запись в браузере».
- Раздел «Расширение» → **«Запись в браузере»**; в попапе видно, какую вкладку записывает; баннер «доступна новая версия».
- **«Встречи» → «Мои встречи»** (только свои, даже для админа). **«Все встречи»** — тот же UI (табы/поиск/теги/календарь) по всем, ошибочные с кнопкой «Переанализировать» (общий компонент `MeetingsView`).
- Календари: кнопка «Подключить» скрыта при подключённом календаре; синтетический `preview@sifox.local` не показывается. Кнопка «Синхронизировать» обновляет и **список** календарей, не только события.
- Пользователи: убран блок приглашений и списки ссылок.

### Коммуникации (Mattermost + Gmail)
- Сбор в `mm_messages` / `email_messages`, инкремент по `sync_state` (по каналу / по юзеру). MM — каналы бота; Gmail — Service Account + DWD по адресам из `users` (синтетический preview исключён).
- Страница `/admin/communications`: просмотр с фильтрами/пагинацией + AI-аналитик. Контекст для AI — **релевантный** (Postgres FTS, `ts_rank`, OR-запрос) за период; учитывает левые фильтры (канал/пользователь).
- В проде заданы `MM_TOKEN`/`MM_SERVER_URL` и `GOOGLE_SERVICE_ACCOUNT_JSON` (DWD авторизован). Диагностический эндпоинт `/api/admin/comms/debug` был временным и удалён.

## Открытые задачи / идеи
- **Имена участников из аватарки**: сейчас извлечение откатано на `text_content()` (в участники попадают мусорные инициалы вроде «АС»). Реальный DOM известен: чистое имя в `span.TextName_BOaIg` (и в атрибуте `title`) — можно сделать точечный фикс на источнике.
- **Mattermost «пингпонг» таймлайна** при одновременной подсветке нескольких спикеров (п.2 фикса спикеров) — не сделано.
- **Дедуп писем по `Message-ID`**: одно письмо нескольким внутренним получателям лежит копиями в каждом ящике (разные gmail id) — при желании дедуп по постоянному `Message-ID`.
- **Срок хранения** сообщений/писем: сейчас бессрочно, политики очистки нет.
- **Авто-обновление расширения**: распакованное не обновляется само; правильный путь — Chrome Web Store (unlisted). Пока только баннер «новая версия».
- Второй проход reanalyze для консистентности тегов между встречами (опционально).

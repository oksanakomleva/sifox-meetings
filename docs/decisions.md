# Важные решения и причины

_Хронология не строгая; группировка по темам._

## Запись и дедупликация
- **Дедуп встреч по `google_event_id`, а не `meeting_url`.** Регулярные встречи на одной постоянной ссылке Телемоста затирали друг друга. Каждое occurrence (`singleEvents=True`) — своя строка; на `meeting_url` снят UNIQUE, добавлен частичный уникальный индекс по `google_event_id`.
- **Перенос встречи = новая запись, старая архивируется.** Терминальную строку (`done`/`error`) не «оживляем» (чтобы не терять транскрипт/аудио): освобождаем у неё `google_event_id` (→ NULL) и создаём новую `pending`. Иначе перенесённая встреча не попадала в «Запланированные» и бот не приходил.
- **Хранить только MP3** (WAV удаляется после конвертации) — экономия объёма Railway-volume; был баг с зависающим ffmpeg, раздувавшим хранилище.
- **Спикер сегмента — по большинству перекрытия** с таймлайном, а не по мгновенному значению в `seg.start`: таймлайн активного спикера опрашивается раз в ~1с и отстаёт, из-за чего пограничные слова уходили не тому спикеру (особенно заметно после склейки реплик в абзацы).
- **Имена участников: откат на `text_content()`.** Попытка «снимать имя без аватарки» через `page.evaluate` в реальном DOM возвращала пусто → у всех «Участник». Откатили (имена важнее косметики со склейкой инициалов). Точечный фикс отложен до известного DOM (`span.TextName_BOaIg`).

## AI
- **Провайдер — OpenAI, не Anthropic.** Переиспользуем существующую инфраструктуру (`AsyncOpenAI`), без нового ключа/зависимости, единый стиль.
- **Отдельная `CHAT_MODEL=gpt-4.1` (окно ~1M) для нагрузки полными транскриптами** (чат, итоги недели, протокол, аналитик коммуникаций). Анализатор-тегирование остаётся на `gpt-4o`. Причина: большие транскрипты не влезают в 128k; gpt-4.1 ещё и дешевле за токен; не меняем разом стоимость/поведение всего.
- **В контекст AI — полные транскрипты, а не протоколы.** Протоколы — выжимка, для вопросов по деталям нужен исходный текст. Везде бюджет по символам (`CHAT_MAX_CONTEXT_CHARS`).
- **Итоги недели кэшируются** (`week_summaries`) и пересобираются только при изменении набора встреч **или промпта** (хэш промпта в сигнатуре) — раньше генерировались на каждый заход (деньги + непостоянство).
- **Теги — по заказчику/проекту/продукту**, с учётом названия встречи и переиспользованием существующих тегов (словарь подаётся в промпт) — чтобы теги были консистентными и пригодными для фильтра, без мелочей-процессов.
- **Контекст AI-аналитика коммуникаций — релевантный (Postgres FTS), а не «последние N».** Чтобы не терять старые релевантные сообщения за период; запрос расширяется до OR, ранжирование `ts_rank`; фолбэк на свежие, если у вопроса нет лексических совпадений.

## Доступ, превью, демо
- **Gmail через Service Account + Domain-Wide Delegation**, а не per-user OAuth. Требование: читать почту всех пользователей из `users` без их участия. Нужен супер-админ Workspace, авторизующий client_id SA на scope `gmail.readonly`. Синтетический `preview@sifox.local` исключён (нет реального ящика).
- **Mattermost — только каналы, где состоит бот** (реалистично без системных прав); токен бота/PAT.
- **Превью «как пользователь» — отдельная кука `preview`, только свой аккаунт, принудительно не-админ.** Раньше превью затирало основную `session` (застревали без выхода) и позволяло смотреть любого. Отдельная кука сохраняет админскую сессию; выход — очисткой куки.
- **Демо-режим — фронтовый слой поверх preview.** Реальные встречи только с тегом `демо` (сам тег скрыт), фейковые звонки и «будущий функционал» — статикой на фронте. Чат в демо эфемерный (история не грузится и не сохраняется на бэке). Цель — показывать продукт без реальных данных и без пометок «демо» для зрителя.
- **`/api/meetings` всегда персональный** (даже для админа) → «Мои встречи»; все встречи — отдельно через `/api/admin/meetings` и `/api/admin/upcoming`. Чёткое разделение «моё» vs «всё».

## Расширение
- **Захват звука активной вкладки** (`tabCapture`), не системного аудио. Следствие/ограничение: десктопные звонки (Телемост/Zoom-десктоп) и звонок в другой вкладке не записываются — только активная вкладка + микрофон. Поэтому в попапе показываем, **какая вкладка** записывается.
- **Авто-обновление невозможно для «распакованного» расширения** (MV3 запрещает удалённый код; нельзя перезаписать свои файлы). Решение на сейчас — баннер «доступна новая версия» (сравнение с `/api/extension/version`); правильный путь на будущее — Chrome Web Store (unlisted).

## Инфраструктура / процесс
- **Схема через `schema.sql` + идемпотентные миграции**, отдельной системы миграций нет — применяется на старте (`CREATE TABLE IF NOT EXISTS`, `ALTER … IF NOT EXISTS`).
- **Проверка локально** перед пушем: `py_compile`, `pytest` (без e2e), `tsc --noEmit`. Node поставлен через winget; на PATH в сессии — только при добавлении `$env:ProgramFiles\nodejs`.
- **Деплой ждёт активные записи** (graceful shutdown) — это намеренно (не терять встречу), но новый деплой может «висеть» до конца записи.
- **Переменные окружения — в Railway Variables**, без хвостовых пробелов в именах (был баг: `MM_TOKEN ` с пробелом не подхватывался). Диагностику делаем временными админ-эндпоинтами под `X-Test-Api-Key`, потом удаляем.
